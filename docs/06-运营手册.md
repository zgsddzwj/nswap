# nswap 运营手册

> 技术只是载体，社区产品的生死在运营。本手册回答：冷启动怎么破、邀请码怎么发、楼长怎么用、时机怎么选。

## 1. 核心认知（来自调研的教训）

1. **鱼塘之死**：没有准入验证的"附近的人"社区必然衰落——我们用邀请码验证守住这一关，**宁慢勿滥**
2. **微信群的优势要接住**：物业/居委会拉群本身就是验证，邀请码就是把这种信任迁移到小程序
3. **氛围先于交易**：Buy Nothing 的经验是"赠送+感谢帖"先跑起来，交易自然发生。冷启动期**主推"送"**，不要一上来就是卖卖卖
4. **一个小区的最低活跃线**：约 30~50 名已验证住户、10+ 在架物品，feed 才"活着"；低于此线用户来了看到空页面就走

## 2. 和居委会/物业谈背书（一次性沟通）

**目标**：请对方在业主群转发邀请码 + （可选）帮忙发"住改商"证明。

**给对方的三个理由**：
1. 减少垃圾堆放、促进物品循环利用（环保叙事，居委会喜欢）
2. 群里刷屏的二手信息有了去处，群更清爽（物业喜欢）
3. 平台不收一分钱、不碰钱，居民之间当面交易（打消顾虑）

**话术要点**：强调"公益便民工具""我们小区自己的闲置交换站""物业/居委会是监督方"。
**给对方的东西**：管理后台楼长账号、邀请码批次专属标记（后台可见是谁发的码）、每月一页数据简报（验证户数/流转件数/减少丢弃估算）。

**注意**：主体是你的个体户（账号归你），对方是"支持方/监督方"而非运营者——这一点在沟通时讲清楚，避免日后权属纠纷。

## 3. 邀请码发放策略

| 批次 | 发放渠道 | 数量 | 说明 |
|---|---|---|---|
| 第 1 批 | 居委会/物业在业主群直接发 | 每楼栋 20 个 | 附一句话介绍+二维码海报 |
| 第 2 批 | 楼长按需定向发 | 不限 | 老住户担保码补位 |
| 常态 | 老住户担保（完成 1 笔交易解锁） | 每人 1 个/同时 | 裂变但可控 |

- 邀请码有效期建议 14 天，作废机制处理泄露
- **不要一次性全小区轰炸**：先 2~3 栋试点，跑通"发布→意向→当面交接→感谢帖"完整案例，拿截图再全量推
- 每个码绑定楼栋 → 用户徽章自动正确，feed 的楼栋筛选立刻可用

## 4. 楼长制度

- 每栋楼 1 名，从首批活跃且完成过交易的用户中邀请（给"楼长"徽章即可，MVP 不做物质激励）
- 职责：帮本栋新邻居答疑、转发邀请码、举报初审（后台可见举报列表）
- 招募话术："帮邻居们管管咱们楼的闲置流转"——荣誉驱动足够，重激励会引来功利型楼长（鱼塘塘主教训：无工具无激励的志愿者会流失，所以系统给了楼长后台工具，比荣誉更实际）

## 5. 启动时机优先级

1. **毕业季（6-7 月）**：教材/小家电/自行车集中出手，供给洪峰
2. **搬家季（年底/春节前）**：大件家具赠送需求爆发
3. **年末大扫除（1-2 月）**：断舍离高峰
4. 日常启动也可以：主打母婴闲置（宝妈群体活跃度最高、复购频次高）

## 6. 内容安全日常巡查

- 每天看一眼后台「待处理举报」（目标 48h 处置）
- mediaCheck 回调记录页巡查 fail 记录是否已自动隐藏
- 关注文本 sec_status=pending 的内容（接口异常降级队列），人工放行或删除
- 违禁品红线（协议已列）：药品/医疗器械、烟花、活体动物、色情、赌博、假冒盗版、个人隐私信息——发现即下架+封禁，不留情面

## 7. 数据看板关注什么

| 指标 | 健康线 | 不健康时做什么 |
|---|---|---|
| 已验证住户 | 周环比增长 | 加大邀请码投放，让居委会再发一轮 |
| 在架物品 | ≥30 | 自己带头发物品（管理员也是住户）；搞"晒闲置"话题 |
| 意向→交易转化 | >50% | 检查是否信息过期（沉底提醒是否生效） |
| 完成后互评率 | >60% | 评价页引导文案优化 |
| 感谢帖 | 每周 ≥3 条 | 交易完成页的感谢入口保持显眼 |
| 爽约率 | <10% | 信用档案公示违约记录（已实现） |

## 8. 风险应对预案

| 场景 | 处置 |
|---|---|
| 居民纠纷（货不对板） | 协议约定当面验货事后不退；楼长调解；情节严重的封禁 |
| 外人混入（非本小区） | 邀请码作废重发；担保链追责（担保人信用连带） |
| 职业贩子刷物品 | 频控已限（日5/架20）；巡查定价异常批量同款，封禁 |
| 舆情/监管问询 | 出示：邀请码准入机制、内容安全记录、举报处置记录、用户协议 |
| 小程序被投诉下架 | 备用类目方案（05-Checklist 第⑥步），收缩功能重新提审 |

## 9. 扩张节奏（多社区）

单社区模型跑通（月活跃交易 ≥100 笔、纠纷率 <5%）后：
1. 新社区复制：同一后端建新 community + 新邀请码批次（数据模型已预留 community_id）
2. 每个社区独立邀请码体系与楼长，feed 天然隔离
3. 跨社区功能（同小区群内交换效率下降后再考虑）
