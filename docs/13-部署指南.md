## 0. 架构一句话

**"前后端"实际是"一个后端镜像 + 一个微信端"**：`backend/Dockerfile` 两阶段构建（node 构建 admin-web → python 运行 FastAPI），管理后台由后端同源服务（`/admin`），不需要单独部署；小程序不"部署"到服务器，走微信开发者工具上传发布。整体后端 + MySQL + COS 都在微信云托管体系内。

```
┌ 原生小程序 ──wx.cloud.callContainer──┐  ┌ 浏览器 ──HTTPS──┐
│  callContainer 自动注入 X-WX-OPENID   │  │ https://域名/admin │
▼                                     ▼▼
┌──────────────── 微信云托管 ─────────────────┐
│ 容器：FastAPI + 管理后台SPA + 定时任务        │
│   ├─ MySQL（云托管数据库，迁移 alembic）      │
│   ├─ COS 对象存储 + CDN（STORAGE_BACKEND=cos）│
│   └─ 开放接口服务（免token调微信API）          │
└─────────────────────────────────────────┘
```

## 2. 路线 A：微信云托管（生产推荐）

### A-1 准备
- 个体户小程序账号 + AppID（`miniprogram/project.config.json` 已填，确认归属）
- 开通微信云托管（cloud.weixin.qq.com）→ 创建环境，记下 **环境 ID**

### A-2 数据库
云托管控制台创建 **MySQL 数据库**（最小规格起步），记下内网连接串：
`mysql+pymysql://用户:密码@内网地址:3306/nswap?charset=utf8mb4`

### A-3 部署后端服务（含管理后台）
1. 云托管创建服务，**服务名 `nswap`**（须与小程序 `CLOUD_SERVICE` 配置一致）
2. 代码来源：**Git 部署**（关联 GitHub 仓库 zgsddzwj/nswap，分支 main）或本地代码上传（上传整个仓库根目录）
3. 构建配置：**Dockerfile 路径 `backend/Dockerfile`**，构建上下文 = 仓库根目录（镜像内自动构建 admin-web）
4. 监听端口 **8000**；开启**公网访问**，得到默认公网域名（腾讯域名，免备案）
5. 环境变量：

| 变量 | 值 | 说明 |
|---|---|---|
| `ENV` / `ENVIRONMENT` | `prod` | |
| `DATABASE_URL` | A-2 内网连接串 | |
| `PUBLIC_BASE_URL` | `https://<公网域名>` | 图片外链与回调前缀 |
| `WX_CALL_MODE` | `cloud` | 容器内免 access_token 调微信接口 |
| `ADMIN_SESSION_SECRET` | **强随机串** | P0-2，不可用默认值 |
| `ENABLE_SCHEDULER` | `true` | 每日沉底/归档扫描 |
| `STORAGE_BACKEND` | `cos` | **生产必须**：容器无状态，local 重启丢全部图片 |
| `COS_SECRET_ID` / `COS_SECRET_KEY` | 腾讯云密钥 | 配合上一项 |
| `COS_REGION` / `COS_BUCKET` | 如 `ap-guangzhou` / `nswap-prod` | |
| `COS_CDN_DOMAIN` | 可选 | 图片走 CDN |
| `SENTRY_DSN` | 可选 | 不填不启用 |
| `RATE_LIMIT_ENABLED` | `true` | |
| `TERMS_VERSION` | `2026-10` | 与小程序端 `TERMS_VERSION` 一致 |

6. 首次部署后（容器起不来时看部署日志，P0-1 已修复不应再出现 1061），用云托管控制台 **WebShell（容器终端）** 初始化一次数据：
```bash

python scripts/seed.py --admin-openid <你的openid>     # 自己设为小程序端管理员
# openid 来源：小程序启动后后端日志 / 或任意接口响应中的 user id 对应记录
```

### A-4 微信侧配置（mp.weixin.qq.com + 云托管控制台）
- **开放接口服务**：云托管控制台开启"微信调用"，`msgSecCheck / mediaCheckAsync / code2session / 订阅消息` 才能免 token 调用
- **消息推送**：mp 后台 → 开发 → 开发设置 → 消息推送，URL=`https://<公网域名>/api/wechat/callback`，明文模式——图片安全检测异步回调入口
- **订阅消息**：申请 4 个一次性模板（新意向/意向被接受/待确认/新评价），模板 ID 同时填到 A-3 环境变量 `MSG_TPL_*` 与小程序 `SUBSCRIBE_TEMPLATES`
- **request/uploadFile 合法域名**：加入云托管公网域名（走 callContainer 理论不需要，加一份保险）

### A-5 小程序发布

## 3. 路线 B：docker compose（本地 / 内网测试）

```bash
docker compose up -d --build
# 管理后台 http://localhost:8000/admin （admin/nswap123，仅限本地）
# 首次初始化：docker exec -it nswap-backend python scripts/seed.py
```

两个已知坑：
- **端口**：compose 后端在 **8000**，小程序本地模式默认连 **8001**（`config/index.ts` 的 `DEV_BASE_URL`）。模拟器把 `DEV_BASE_URL` 改回 `http://127.0.0.1:8000`，或弃 compose 改手动 `uvicorn --port 8001`（AGENTS.md 约定）。此不一致记录在 docs/12 P1-9。
- **mock 语义**：compose 的 `WX_CALL_MODE=mock` 意味着内容安全全放行、订阅消息不发，**仅限测试**。

## 4. 路线 C：自建服务器（华为云等，已原生支持）

代码原生支持三模式（本地 / 云托管 / 自建），自建走 **code2session 登录 + Bearer token**，不再依赖云托管注入的 `X-WX-OPENID`。适合已有优惠服务器、或想完全掌控部署的情形。

**选型提醒**：
- 规格认准 **S6/S7 共享标准型**，避开 **T6 突发性能型**（CPU 积分制，常驻 MySQL+FastAPI 会耗尽积分被降速）
- **图片必须走对象存储 + CDN**（华为云 OBS 兼容 S3 端点，或继续用腾讯云 COS），不要从服务器出图流量；接口 JSON 对带宽要求很低
- 域名需 **ICP 备案**（华为云接入备案，免费，1~2 周）——小程序本身的备案同样必须

### C-1 服务器准备
```bash
# 1) 装 Docker（华为云 Ubuntu/CentOS 均可）
curl -fsSL https://get.docker.com | sh && systemctl enable --now docker
# 2) 安全组：只放行 22 / 80 / 443，其余全关
```

### C-2 拉代码 + 生产环境变量
```bash
git clone https://github.com/zgsddzwj/nswap.git && cd nswap
cp .env.example .env && vi .env
```
`.env` 必改项：

| 变量 | 值 |
|---|---|
| `ENV` / `ENVIRONMENT` | `prod`（dev 后门与假身份自动关闭） |
| `DATABASE_URL` | `mysql+pymysql://nswap:强密码@mysql:3306/nswap?charset=utf8mb4`（compose 内网名）或云数据库内网串 |
| `PUBLIC_BASE_URL` | `https://你的域名`（图片外链） |
| `WX_CALL_MODE` | `token`（自管 access_token） |
| `WX_APPID` / `WX_SECRET` | 小程序后台「开发管理-开发设置」获取 |
| `ADMIN_SESSION_SECRET` | 强随机串 |
| `AUTH_TOKEN_SECRET` | 强随机串（留空则复用上面那把） |
| `STORAGE_BACKEND` + `COS_*` | `cos` + 对象存储凭据（OBS 填 S3 兼容 endpoint） |
| `RATE_LIMIT_ENABLED` | `true` |
| `MSG_TPL_*` | 4 个订阅消息模板 ID（申请后回填） |

### C-3 起服务 + 初始化
```bash
docker compose -f docker-compose.prod.yml up -d --build   # mysql + backend（仅绑 127.0.0.1:8082）
# 容器 CMD 启动时会自动执行 alembic upgrade head；等健康检查通过后初始化数据：
docker compose -f docker-compose.prod.yml exec backend python scripts/seed.py --skip-demo
docker compose -f docker-compose.prod.yml exec backend python scripts/seed.py --admin-openid <你的openid>
```

> ⚠️ **不要在容器刚 `up` 时并发手动跑 `alembic upgrade head`**（容器 CMD 里已经在跑），
> 并发迁移会撞出「Table already exists」且版本表为空 → 容器启动死循环。
> 已发生时按此恢复：`stop backend` → 重建空库（DROP/CREATE DATABASE）→
> `run --rm --no-deps backend alembic upgrade head`（只跑这一次）→ seed → `up -d backend`。

### C-4 Nginx + HTTPS

两种接法，按服务器现状选：

**A) 域名直接指向本机（独立部署）**：用 `deploy/nginx.conf.example`（listen 443 + certbot 证书）。

**B) 与既有网关共存（子路径隔离，多项目同机，推荐）**：
把 `deploy/nginx.gateway-location.conf.example` 的 location 块并入既有网关 server 块，并让管理后台按前缀构建
（`docker-compose.prod.yml` 已配 `ADMIN_BASE=/nswap/admin`）。此时各项地址都带前缀：

| 项 | 值 |
|---|---|
| 管理后台 | `https://域名/nswap/admin` |
| API / 图片 | `https://域名/nswap/api/**`、`https://域名/nswap/uploads/**` |
| `PUBLIC_BASE_URL` | `https://域名/nswap`（图片外链带前缀，否则图片 404） |
| 小程序 `SELF_HOSTED_BASE_URL` | `https://域名/nswap` |
| 微信消息推送回调 | `https://域名/nswap/api/wechat/callback` |

```bash
apt install -y nginx
cp deploy/nginx.conf.example /etc/nginx/conf.d/nswap.conf   # 方案 A；方案 B 见上表
certbot --nginx -d 你的域名          # 或换华为云免费证书，见示例注释
nginx -t && nginx -s reload
```
> **备案未就绪的过渡期**：同样走方案 B，前置一个 `listen 80 + server_name 为公网 IP` 的 server 块
> （或直接并入 default_server 网关），仅用于浏览器验证与管理后台；正式接小程序前必须换 HTTPS 域名。
>
> 示例已把 `X-Forwarded-For` **覆盖**为 `$remote_addr`（而非追加），客户端伪造 XFF 在边缘被丢弃，顺带缓解 docs/12 P1-3 的限流绕过面。

### C-5 小程序端
`miniprogram/config/index.ts` 两处：
```ts
export const LOCAL_DEV = false;
export const SELF_HOSTED_BASE_URL = "https://你的域名";        // 子路径隔离部署时带前缀：https://你的域名/nswap
```
然后微信后台把该域名加入 **request / uploadFile 合法域名**（均需 HTTPS + 备案），开发者工具上传体验版验证。
> 管理后台入口由基址自动推导（`基址 + /admin`），无需单独配置。
