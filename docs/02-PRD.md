# nswap PRD：功能架构与页面流转

> 产品名：nswap（邻里闲置交换站）｜ 形态：微信小程序 + Web 管理后台
> 版本：MVP v1.0 ｜ 依据：[01-调研报告](./01-调研报告.md) 五大支柱

## 1. 产品定位

**一句话**：以小区为单位的"邻里闲置交换站"，替代小区微信群刷屏卖闲置。

**目标用户**：同一小区的住户（邻里半熟人场景）。

**三条设计原则**：
1. **准入验证是地基**——没有验证的邻居只是"附近的陌生人"
2. **状态机消灭"还在吗"**——商品必须有生命周期管理
3. **赠/求/谢最轻流程是氛围引擎**——赠送免定价，感谢帖给社区情感回报

**关键边界（合规）**：平台只做信息撮合与流程留痕，**不介入资金**（无支付、无订单、无佣金）；钱货线下当面两清；页面文案避开"购买/订单/支付"，统一用"交换/赠送/约定"。

## 2. 角色定义

| 角色 | 获得方式 | 权限 |
|---|---|---|
| 游客（未验证） | 微信登录即游客 | 只可浏览 feed/详情/留言，不可发布、不可留意向 |
| 住户（已验证） | 邀请码 / 老住户担保 / 管理员人工审核 | 全部住户功能 |
| 楼长 | 超管在后台指定 | 住户权限 + 协助处置举报 |
| 超级管理员 | 系统种子账号 | Web 管理后台全部权限 |

## 3. 功能架构总览（7 大模块）

```
小程序端（住户视角）                              Web 管理后台（/admin）
├─ M1 身份与准入  登录/验证/资料/角色              └─ M7 管理端
├─ M2 发布管理    四形态发布/图片/续期/下架              登录/看板/邀请码/内容巡查/
├─ M3 浏览发现    feed/筛选/搜索/详情/收藏/留言          举报处置/用户管理/内容安全记录
├─ M4 交易闭环    意向/挑选/约定/双向确认/互评/感谢
├─ M5 消息通知    通知中心/轻会话/订阅消息
└─ M6 我的与信用  信用档案/我的发布/收藏/交易/举报/协议
```

## 4. 模块详细设计

### M1 身份与准入

**功能点**：
| 功能 | 说明 |
|---|---|
| 微信静默登录 | 启动时自动完成；openid 由云托管 callContainer 注入，无需用户操作 |
| 邀请码验证（主通道） | 输入居委会/物业/楼长发放的邀请码 → 绑定楼栋 → 成为已验证住户；一码一户，按楼栋批次生成 |
| 老住户担保 | 已验证且完成过 ≥1 笔交易的住户可生成 1 个"担保码"（同时只能有 1 个未使用），新邻居凭码验证；系统记录担保关系 |
| 人工审核 | 上传业主凭证图片（房产证/物业单据，仅管理人员可见）+ 楼栋 → 超管在后台通过/驳回 |
| 资料编辑 | 昵称、头像（微信头像昵称填写能力）、楼栋单元（验证后锁定楼栋，改楼栋需重新验证） |
| 身份徽章 | "X栋·已验证邻居"，**到栋不到户**（隐私平衡） |

**入口与跳转**：
```
启动 app → 静默登录 → home
home 顶部横幅「完成小区验证，解锁发布与交换」 ──> verify 页
mine「小区验证」卡片 ──> verify 页
verify 成功 → 返回 home，横幅消失，发布/意向功能解锁
```

### M2 发布管理

**四形态差异化表单**（一张表单按 type 显隐字段）：
| 字段 | 出售 sell | 赠送 give | 换物 swap | 求购 want |
|---|---|---|---|---|
| 图片 1-9 张 | ✅ | ✅ | ✅ | 可选 |
| 标题 | ✅ | ✅ | ✅ | ✅ |
| 分类（9 类） | ✅ | ✅ | ✅ | ✅ |
| 成色（5 档） | ✅ | ❌ 免 | ✅ | ❌ |
| 价格（元） | ✅ | ❌ 免定价 | ❌ | ❌ |
| 可小刀开关 | ✅ | ❌ | ❌ | ❌ |
| 描述 | ✅ | ✅ | ✅ | ✅ |
| 想换什么 want_desc | ❌ | ❌ | ✅ | ✅（想要什么） |
| 出价预算 | ❌ | ❌ | ❌ | ✅ 可选 |

- 分类：母婴 / 图书 / 家电 / 家具 / 服饰 / 数码 / 运动 / 厨具 / 其他
- 成色：全新未拆 / 99新 / 9成新 / 明显使用痕迹 / 功能正常有磨损
- 图片：压缩后上传 → 后端 mediaCheckAsync 异步检测，违规自动隐藏
- 文案：标题+描述先过 msgSecCheck 再入库

**管理功能**：编辑（仅在售且无进行中交易）、手动下架（归档）、删除、免费续期（72 小时冷却，防止刷屏）

**自动化规则**：
- 挂出 14 天无互动（浏览/意向/留言）→ 自动"沉底"（从首页 feed 消失）+ 通知作者"还在吗？一键续期 / 确认送出 / 下架"
- 沉底 30 天未处理 → 自动归档

**频控（反职业贩子）**：每人同时在架 ≤ 20 件；每天发布 ≤ 5 件。

**入口与跳转**：
```
TabBar「发布」→ publish 四宫格（我要卖/我要送/我要换/我想要）
  ──> publish/edit?type=sell|give|swap|want 表单页 ──发布成功──> detail（预览）
mine ──「我的发布」──> my-items（按状态 tab）──管理──> detail（编辑入口）
```

### M3 浏览发现

**首页 feed**：
- 顶部：搜索框（→ search 页）+ 筛选条（形态：全部/卖/送/换/求；分类 9 选 1；楼栋：全部/N栋）
- 顶部横滑「邻里感谢」卡片：最近 10 条感谢帖（社区氛围展示）
- 主体：双列瀑布流「今日新出」，按 last_active_at 倒序，游标分页
- 商品卡：首图、标题、价格（或"免费送""可交换""求"角标）、成色标签、楼栋、发布时间、状态角标
- 状态角标：在售（默认）/ 已预约 / 已完成 / 已沉底

**详情页 detail**：
- 图片轮播（违规图自动隐藏）、标题、价格、成色、分类、楼栋、描述、想换什么
- 卖家信息行：头像+昵称+"X栋·已验证"徽章 → 点击进 profile
- 数据行：浏览量、收藏数、发布时间
- 公开留言板（先检后显，任何人可留言——游客也可看不可发）
- 底部操作区（按角色与状态动态）：
  - 我是买家且在售：主按钮「我想要」（求购帖则显示「我可以提供」）+ 次按钮「收藏」
  - 意向已被接受：「和 TA 聊聊」→ chat
  - 我是作者：编辑 / 下架 / 查看意向（有新意向时红点）
  - 已预约/已完成：只读 + 查看交易
- 举报入口（右上角 ··· 菜单）

**入口与跳转**：
```
home ──商品卡──> detail ──卖家行──> profile
search ──结果卡──> detail
my-items / favorites ──卡──> detail
```

### M4 交易闭环（核心）

**完整状态流转**：
```
物品：on_sale ──卖家接受某意向──> reserved ──双方确认完成──> completed
         ↑                            │
         └────取消交易（回滚）─────────┘
交易：pending ──约定时间地点──> arranging（双方可见）
        ──A确认──> A已确认 ──B确认──> completed（触发互评）
        ──任一方取消──> cancelled（记入取消方信用事件）
意向：pending ──卖家接受──> accepted ──交易完成──> done
                ──卖家拒绝──> rejected（可重新提交）
```

**流程节点**：
1. **我想要**（want-sheet 弹层）：留言（必填，如"我家娃正好需要"）+ 出价（仅可小刀物品，低于定价的出价）+ 换物场景填写"我用Y换"。提交后订阅消息通知卖家
2. **卖家挑选**（wants 页）：意向列表（含出价者信用档案摘要），自由挑选接受（**不先到先得**）；接受后自动创建轻会话+交易单，物品转"已预约"停止收新意向，通知买家
3. **约定**（chat 内「去约定」→ trade 页）：交接方式三选一（当面见面 / 放门口自取 / 物业前台代交）+ 时间（+地点备注）；双方均可填写，对方可见
4. **双向确认**：交接完成后双方各自点击「确认完成」（换物双方都确认才关单）；单方确认后提醒对方
5. **互评**（review 页）：1-3 星（满意/一般/不满意）+ 可选留言；互评后对彼此可见
6. **感谢帖**（可选）：交易完成后一键发布"感谢X栋的邻居送了..."，展示在首页横滑区
7. **取消**：取消方记入信用事件（爽约记录）；物品回滚在售、意向回滚待选

**防骚扰**：会话仅在意向被接受后开放；留言板内容过审后展示。

**入口与跳转**：
```
detail ──「我想要」──> want-sheet（页内弹层）──提交──> 返回 detail（提示已通知卖家）
detail ──「查看N个意向」──> wants ──接受──> chat（自动开场）
messages ──会话──> chat ──「去约定」──> trade
messages ──通知（被接受/待确认）──> trade
trade ──双方均确认──> review ──评价+可选感谢──> my-trades
mine ──「我的交易」──> my-trades（进行中/已完成 tab）──> trade（查看）
```

### M5 消息通知

**通知中心**（messages 页上半部，tab 切换）：
- 通知类型：收到新意向 / 意向被接受 / 意向被拒绝 / 交易待确认 / 交易已完成 / 收到评价 / 物品沉底提醒 / 系统
- 每条通知可点击直达对应页面（detail / trade / my-items）

**会话列表**（messages 页下半部）：按最近消息排序，未读红点。

**轻会话 chat**：纯文本消息，5 秒轮询增量拉取（since 游标）；顶部物品卡常驻（点击回 detail）；「去约定」按钮常驻。

**微信订阅消息**（一次性，4 模板）：新意向（→卖家）/ 意向被接受（→买家）/ 待确认提醒（→未确认方）/ 收到评价。**触发时机**：用户执行关键动作前（提交意向/接受意向/确认完成）调用 `wx.requestSubscribeMessage`。

### M6 我的与信用

**信用档案**（mine 顶部卡片 + profile 他人视角）：
- 认证徽章「X栋·已验证邻居」、加入时间
- 客观数据：送出 N 件 / 换成 N 件 / 卖出 N 件、好评率（好评/(好评+中评+差评)）、被感谢 N 次、爽约/违约 N 次
- **不做综合评分**（多抓鱼黑箱教训），只列原始数据

**我的页面清单**：我的发布（on_sale/reserved/completed/archived tab）/ 我的收藏 / 我的交易（进行中/已完成）/ 小区验证 / 用户协议 / 隐私政策 / 举报与反馈 /（管理员可见）管理后台入口（复制链接）。

### M7 Web 管理后台（/admin，Jinja2+Bootstrap）

| 页面 | 功能 |
|---|---|
| 登录 | 独立账号密码（与小程序账号体系隔离） |
| 看板 | 用户数/已验证数/物品数/交易数/待处理举报数 + 最近动态 |
| 邀请码管理 | 按楼栋批量生成（选楼栋+数量+有效期）、列表、复制、作废；导出给居委会/物业/楼长分发 |
| 内容巡查 | 全量物品列表（筛选状态/类型/楼栋），强制下架 |
| 举报处置 | 待处理列表 → 处置（下架物品/隐藏留言/封禁用户）或驳回 |
| 用户管理 | 列表（含游客）、人工验证审核（查看业主凭证图）、封禁/解封、设/撤楼长 |
| 内容安全记录 | mediaCheckAsync 回调记录（trace_id、结论、涉及对象） |

## 6. 内容安全与频控（合规硬约束）

| 对象 | 机制 |
|---|---|
| 物品标题/描述、留言、会话消息、感谢帖、用户昵称 | msgSecCheck 同步先检后发；接口异常时入库为「待审」状态，仅作者和管理员可见（fail-closed 降级） |
| 物品图片、业主凭证图 | mediaCheckAsync 异步检测，回调违规自动隐藏（先发后撤） |
| 举报 | 物品/留言/用户三个维度，48 小时内处置（目标） |
| 频控 | 发布 日≤5、在架≤20；意向 每物品每用户 1 个活跃意向；担保码 同时 1 个 |

## 7. 非目标（V2 及以后）

线上支付担保（transactions.payment 字段已预留）/ 多社区切换 / AI 辅助发布（拍照识别品类+建议描述+参考价）/ 交换积分（限定品类）/ 地图视图 / WebSocket 实时会话 / 互评匿名化 / 快递代寄。
