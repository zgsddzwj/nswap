## 2. 关键机制

### 2.1 鉴权：openid 注入，无 token

- 生产（云托管）：小程序用 `wx.cloud.callContainer()` 调后端，云托管在请求头自动注入 `X-WX-OPENID`（需在云托管控制台开启「微信调用」）。后端信任该头（云托管环境内不可伪造），直接识别用户——**全程无登录态 token 管理**
- 本地开发：`.env` 中 `ENV=dev` 时，小程序 api 层走 `http://127.0.0.1:8000`，请求头携带 `X-DEV-OPENID`（mine 页有开发者身份切换器，便于模拟买卖双方）；后端无 X-WX-OPENID 时回退读取它
- 游客（未验证住户）可读 feed/详情，写操作（发布/意向/留言）返回 403

### 2.2 微信接口调用：三种模式（`WX_CALL_MODE`）

| 模式 | 说明 | 场景 |
|---|---|---|
| `mock` | 全部直接通过（文本 pass / 图片 pass / 发送 noop） | 本地开发、pytest |
| `cloud` | 容器内直接请求 `api.weixin.qq.com` 免 access_token（云托管「开放接口服务」） | 云托管生产 |
| `token` | 用 WX_APPID/WX_SECRET 自取并缓存 access_token | 自建服务器部署 |

所有微信调用集中在 `services/wechat.py`，失败不阻塞主流程（内容安全失败降级策略见 2.3）。

### 2.3 内容安全（合规硬约束，`services/sec_check.py`）

```
文本（标题/描述/留言/消息/感谢帖/昵称）:
  msgSecCheck(同步) ──pass──> 正常入库展示
        │risk → 直接拒绝（400 提示修改）
        └error(接口异常) → 入库 sec_status=pending：仅作者与管理员可见（fail-closed，待人工）
图片（物品图）:
  上传入库 sec_status=pending → mediaCheckAsync(异步) → 微信回调 /api/wechat/callback
        ├─ pass 回调 → sec_status=pass
        └─ risk 回调 → sec_status=fail → 立即从展示层隐藏
```

### 2.4 通知：站内通知 + 一次性订阅消息

- 站内通知（notifications 表）为基准，保证不丢
- 微信订阅消息为增强：关键动作前 `wx.requestSubscribeMessage`，授权记录到 msg_subscriptions 表（配额计数），`services/notify.py` 发送时消耗配额，无配额则跳过
- 4 个模板：新意向(卖家) / 意向被接受(买家) / 待确认提醒 / 收到评价

### 2.5 图片存储

- MVP：`POST /api/uploads` 接收 multipart 文件存容器 `uploads/` 目录，`/uploads/{file}` 静态服务；URL = `PUBLIC_BASE_URL + path`
- **云托管容器文件系统是临时存储**（重新部署会丢），生产上云前需按 `docs/05` 第④步切换为云托管对象存储/COS（代码集中在 `uploads` router，替换 `save_upload()` 一个函数即可）
- 图片上传前小程序端压缩（`wx.compressImage`，质量 70）

### 2.6 定时任务（`services/expiry.py`，APScheduler）

每日 03:00 扫描：`last_active_at` 超 14 天的 on_sale 物品 → sunk + 通知作者；sunk 超 30 天 → archived。

### 2.7 交易状态机（`api/trades.py` 集中守护）

```
物品:  on_sale →(接受意向)→ reserved →(双方确认)→ completed
                        ←(取消，回滚)←
交易:  pending → arranged → a_confirmed/b_confirmed → completed
              └──────────→ cancelled（记取消方信用事件）
```

所有状态迁移在 API 层做前置校验（非法迁移返回 409），核心规则有 pytest 覆盖。

## 6. 本地开发与部署

### 本地（无需真实 AppID）
```bash
docker compose up -d mysql     # 或整个 docker compose up
cd backend && python -m venv .venv && .venv/Scripts/pip install -r requirements.txt
.venv/Scripts/python scripts/seed.py          # 建表+超管+示例数据
.venv/Scripts/uvicorn app.main:app --reload   # http://127.0.0.1:8000
# 管理后台 http://127.0.0.1:8000/admin  默认 admin / nswap123（务必改）
```
小程序：微信开发者工具导入 `miniprogram/`，详情勾选「不校验合法域名」，`config/index.ts` 保持 `LOCAL_DEV=true`。

### 生产（云托管）
1. 开通云托管环境，关联小程序；创建 MySQL 实例并记下连接串
2. 代码上传方式部署 `backend/`（或接入 Git 自动部署），环境变量按第 5 节配置（WX_CALL_MODE=cloud，PUBLIC_BASE_URL=云托管默认公网域名）
3. 首次部署后执行 `alembic upgrade head` 与 `scripts/seed.py`（改掉默认密码）
4. 小程序 `config/index.ts` 改为云托管环境配置；把云托管公网域名加入小程序 uploadFile/request 合法域名
5. 微信后台配置消息推送（URL=云托管域名/api/wechat/callback，明文模式）与 4 个订阅消息模板

### 迁移到自建服务器（无锁定保障）
FastAPI 工程是标准 Docker 镜像：任何云服务器 `docker compose up` 即可运行；需自购域名+ICP备案，`WX_CALL_MODE` 改 `token`。数据用 `mysqldump` 迁移。
