### P0-1 迁移链断裂，全新部署 crash loop
- `alembic/versions/f91b070d8b1d_initial_schema.py:136` 与 `alembic/versions/d9a4c1f83b72_production_hardening.py:36` **重复创建同名索引 `ix_items_feed`** → MySQL `alembic upgrade head` 报 1061 Duplicate key name；`backend/Dockerfile` CMD 每次启动执行迁移 → 云托管全新部署必崩。
- 次要断点：`alembic/versions/c5f8d3e27a91_multitenant_saas.py:37` 用 `op.create_foreign_key`，SQLite 方言不支持（未用 batch_alter_table）。
- 根因：测试与 CI 全走 `Base.metadata.create_all`，从不执行迁移链。
- 修法：删除 d9a4c1f83b72 中重复索引；c5f8d3e27a91 改 batch 模式；CI 增加"空库 alembic upgrade head"任务。

### P0-2 管理后台会话密钥默认值 `dev-secret`，无生产守卫（建议按 P0 对待）
- `backend/app/core/config.py:20` 默认值 + `docker-compose.yml:31` 显式传 `dev-secret`。
- SessionMiddleware 为签名 cookie：密钥公开已知 ⇒ 任何人可伪造 admin_id 接管管理后台（读业主凭证图、导出用户、封禁住户）。
